# 08. Recursive Identity Synthesis

## Reversible Memory and Provenance Index

### Original vision

Compress old memories into intuition without losing the self.

### Evidence boundary

An archive or summary does not preserve a person’s consciousness, and compression can discard information.

### Buildable proposal

Create derived category indices referencing unchanged source records; store a digest and retain originals. Start with synthetic notes.

### Testable hypothesis

Reversible indexing makes every derived category traceable to source records and preserves user correction.

### Baseline comparison

Destructive summarization that discards original notes.

### Measurements

Source-link coverage, retrieval accuracy, correction success, accidental deletion rate, and cost of retaining originals.

### Next implementation steps

Add consent scopes and local encryption; evaluate retrieval on synthetic notes; add export and deletion workflows before personal-data pilots.

### Failure modes

Confabulation, privacy exposure, inaccurate categories, therapeutic overclaims, and insufficient deletion semantics.

### Sponsor or collaborator fit

Personal knowledge-management maintainer or digital-archive partner; propose a privacy-preserving retrieval benchmark.

### Runnable source

`labs.core.memory_index` in `labs/core.py`. Run all examples with `python -m labs.demo`; inspect `tests/test_labs.py`.

### Six-week milestone proposal

Weeks 1–2: specify data and assumptions with an independent reviewer. Weeks 3–4: extend the demonstrator and run a preregistered baseline comparison. Weeks 5–6: publish reproducible results, failure cases, and a go/no-go recommendation. This schedule is a planning estimate, not a commitment or evidence of feasibility beyond the bounded software task.

Success means a reproducible result and honest limitations, including a null or negative result. No lab, clinical, animal, radiation, or environmental intervention is authorized by this proposal.
